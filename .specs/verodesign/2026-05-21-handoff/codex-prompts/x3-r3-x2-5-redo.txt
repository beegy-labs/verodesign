### A. React-only composite 페이지 5 건의 CEM marker 정책

대상: `docs/llm/components/{app-shell,bento-grid,entry-dialog,glass-surface,theme-toggle}.md`

이들은 Lit 엘리먼트가 아니라 `@verobee/design-react` 의 React composite 또는 prose-only 가이드. `packages/design-elements/dist/custom-elements.json` 에 declaration 없음 → generate-component-api.mjs 의 `componentMeta` 에 등록 불가.

다음 중 하나로 정합 회복:

1. (선호) prose-only 정책 명시: 페이지 상단(또는 frontmatter 인접) 에 `> Docs format: prose-only (React composite — no Custom Element Manifest).` 한 줄 + `## API` 섹션은 수기 props 표 유지. CEM marker 는 적용하지 않음. 그 대신 `dev-best-practices.md` + `decisions.md` 의 "Component canonical docs" 정책에 **"Lit 엘리먼트 = prose + CEM auto-gen / React-only composite = prose + 수기 API table (CEM marker 없음)"** 한 줄 추가.
2. 또는 generator 가 React-only 페이지에 빈 CEM:START/END 블록을 stub 으로 삽입하도록 확장.

선택 사유 한 줄 보고. 어느 쪽이든 페이지 형식이 일관성 갖도록.

### B. design-elements src 의 `*-bg` 토큰 잔여 broken ref

이건 X2-2 후속 cleanup 인데 X2-5 redo 시점에 발견되었음. **반드시 같이 처리**.

`packages/design-elements/src/components/badge/vds-badge.ts` 가 다음을 참조:

```
var(--vds-theme-status-error-bg)
var(--vds-theme-status-success-bg)
var(--vds-theme-status-warning-bg)
var(--vds-theme-status-info-bg)
```

그런데 `packages/design/dist/css/core.css` 가 실제로 발행하는 변수는 `--vds-theme-{error,success,warning,info}-bg` (status 네임스페이스 없음). 즉 badge soft variant 4 개 (`tone="destructive|success|warning|info"` + `variant="soft"`) 가 깨짐.

확인 명령:
```sh
grep -o "vds-theme-status-.*-bg\b" packages/design-elements/src/components/badge/vds-badge.ts | sort -u
grep -o "vds-theme-.*-bg\b" packages/design/dist/css/core.css | sort -u
grep -E "(error|success|warning|info)-bg" packages/design/tokens/semantic/core.json
```

수정 방향 두 가지 중 택1, 사유와 함께 보고:

1. (선호) **src ref 를 원본으로 되돌림** — badge.ts 의 `var(--vds-theme-status-{error,success,warning,info}-bg)` → `var(--vds-theme-{error,success,warning,info}-bg)`. 다른 src 컴포넌트(`button.ts / checkbox.ts / stat-tile.ts / text.ts / toast.ts`) 도 `*-bg` 참조 있으면 동일 패턴으로 점검 후 통일.
2. **tokens/semantic/core.json 에서 `*-bg` 4 개 + `neutral-bg` 를 `status.*` 네임스페이스 밑으로 옮김** — 이건 X2-2 토큰 마이그레이션의 의도된 연장으로 볼 수 있음. 단 X2-2 SDD 가 명시적으로 정의하지 않은 추가 변경이므로 추가적 cross-check 필요.

빌드 후 다음 검증:
```sh
pnpm --filter @verobee/design-elements build
# 깨진 ref 0 확인
grep -nE "var\(--vds-theme-(status-)?(error|success|warning|info|neutral)-bg\)" packages/design-elements/dist/components/*/*.js | head -20
# 발행되는 토큰 ↔ src 참조 정합
diff <(grep -oE "var\(--[a-z0-9-]+\)" packages/design-elements/dist/components/badge/vds-badge.js | sort -u) <(grep -oE "var\(--[a-z0-9-]+\)" packages/design/dist/css/core.css | grep -oE "var\(--vds-theme-[a-z-]+\)" | sort -u) || true
```

src ref 0 broken, 빌드 PASS, dist 출력 정합 확인 후 보고.
